# PyRuntimeKit 0.1.0a4 - Process & Subprocess Qualification

**Milestone:** 0.1.0a4 - Process & Subprocess Execution  
**Stage:** PR 35 - milestone qualification  
**Release:** deferred to PR 36  
**Package version during qualification:** 0.1.0a3

## Purpose

Qualify the implementation delivered by PR 29 through PR 34, before
promoting the package version or publishing a release.

This qualification is designed to run alongside all previously established
Domain, RuntimeKernel, InlineExecutor, AsyncExecutor and ThreadExecutor
regression suites.

## Authority and compatibility

```text
RuntimeKernel   = Run lifecycle authority
Runner          = application-level progression
Executor        = concrete execution mechanism
ExecutionContext = attempt-scoped explicit context
Runtime.submit  = synchronous, InlineExecutor-backed API
```

The a4 backends must not change the public root API or pretend to create
a public async/process/subprocess Runtime facade.

## Executed qualification dimensions

| Dimension | Qualification |
| --- | --- |
| Legacy API | Runtime.submit / RunHandle unchanged |
| Child process | real child PID and explicit ExecutionContext values |
| Result transport | pickle round-trip, existing ExecutionResult preservation |
| Failure transport | ordinary, input serialization and result serialization distinguished |
| Subprocess command | explicit argv without an implicit shell |
| Subprocess diagnostics | cwd/env, stdout, stderr, exit code |
| Subprocess failure | non-zero exit and launch errors distinct |
| Process backpressure | cancelled await retains slot until child completion |
| Subprocess cleanup | cancellation waits for termination and releases slot |
| Close | active subprocess survives close; subsequent submissions rejected |
| Capabilities | exact advertised sets, no inference of unsupported guarantees |
| Architecture | no kernel/application/API dependency on process backend |
| Deferred scope | no durable/remote/distributed runtime, workers or sandboxing |

Unit conformance from PR 34 remains the reusable backend contract; the
qualification suite validates the entire milestone and compatibility gates.

## Qualification gates

The CI run must pass on the **exact PR head**, and again after the squash
merge on **main**, including:

- Ruff lint and format
- mypy strict
- all pytest suites, including earlier milestone qualifications
- at least 95% overall line/branch coverage as configured
- build sdist and wheel
- validate the typed wheel
- clean installation and smoke test from the wheel

Specific run IDs, coverage, test count and SHA are to be recorded from CI
evidence. Do not assert that these gates passed before the workflows finish.

## Intentional exclusions

No change to version metadata or trusted publishing in PR 35.

Not part of the 0.1.0a4 qualification:

- timeout or deadline control
- hard process termination guarantees
- durable Store, checkpoint or recovery
- remote or distributed ownership
- sandbox/security isolation guarantees
- dynamic user-facing Runtime backend selection
- serializer plugins or persistence of pickle payloads

## Release handoff

PR 36 will update the version to `0.1.0a4`, prepare the release notes,
and verify release provenance, artifacts and publication after all qualification

# PyRuntimeKit 0.1.0a1 — Domain Foundations

PyRuntimeKit 0.1.0a1 introduces the domain foundation: Workload, Run, Attempt, Failure, Results, Domain Events and Run lifecycle invariants. No execution backend or persistence guarantee is included yet.

## What is included

This first pre-alpha release establishes a typed, infrastructure-independent domain core for the runtime.

### Domain contracts

- semantic UUID-backed identifiers for Run, Workload, Failure, Artifact and Event;
- one-based `AttemptNumber`;
- canonical `RunState` lifecycle states;
- Workload, WorkloadRef, WorkloadDescriptor and ResourceHints;
- Run aggregate, monotone RunVersion and schema-versioned RunSnapshot;
- immutable Attempt and terminal AttemptOutcome;
- normalized durable Failure model and normative failure taxonomies;
- generic backend-neutral `ExecutionResult[T]` and logical `RunResult[T]`;
- immutable `ArtifactRef`;
- immutable versioned Run domain events.

### Lifecycle laws

The release includes the canonical Run transition matrix and pure validators for:

- allowed/forbidden Run transitions;
- terminal-state irreversibility;
- exact Attempt progression;
- retry RunId preservation;
- terminal timestamp consistency;
- success/failure evidence consistency for the currently modeled facts.

The transition qualification covers every `RunState × RunState` pair.

### Architecture guarantees

The `domain/` package is qualified to remain independent from infrastructure and higher runtime layers.

Automated architecture tests reject dependencies on execution/concurrency primitives, persistence clients, distributed systems tooling, observability SDKs and higher-level frameworks.

The package is PEP 561 typed and the CI verifies that `pyruntimekit/py.typed` is present in the built wheel.

## Explicit non-goals

This release does not yet provide:

- RuntimeKernel;
- Runtime.submit();
- RunHandle;
- Runner/application orchestration;
- Inline/Async/Thread/Process executors;
- persistence stores;
- checkpoints;
- effects/outbox;
- workers;
- heartbeats;
- leases/fencing;
- distributed recovery;
- OpenTelemetry integration;
- security sandboxing;
- PyAgentsKit/PyScheduleKit adapters.

Those capabilities belong to later milestones.

`0.1.0a2 — Runtime Kernel` starts the first executable vertical slice:

RuntimeKernel

Runner

   ↓

   ↓

The immediate next implementation step is the RuntimeKernel, which will own transition application, RunVersion increments, terminal protection and domain-event creation while remaining independent from workload execution and persistence.

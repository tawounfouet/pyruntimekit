# ADR 0009 — SimpleRunner orchestrates; RuntimeKernel owns lifecycle\n\n- **Status:** Accepted\n- **Date:** 2026-10-25\n\n## Context\n\n`0.1.0a2` now has a RuntimeKernel and an immutable ExecutionContext, but no component yet coordinates an execution attempt.\n\nThe target model distinguishes:\n\n```text\nRuntimeKernel = lifecycle rules\nRunner        = orchestration\nExecutor      = concrete execution\n```\n\nPR 15 precedes the public Executor package scheduled for PR 16.\n\n## Decision\n\nIntroduce `pyruntimekit.application.SimpleRunner` as the first synchronous local orchestrator.\n\nIt accepts one already-configured structurally typed executor and progresses a Run through exactly one execution attempt:\n\n```text\nQUEUED Run\n   + Workload\n      │\n      ▼\nRuntimeKernel.StartRun\n      │\n      ▼\nRUNNING Run\n      │\n      ▼\nExecutionContext\n      │\n      ▼\nconfigured executor\n      │\n      ▼\nExecutionResult\n      │\n      ├── success -> RunResult -> CompleteRun\n      └── failure -> Failure   -> FailRun\n      │\n      ▼\nterminal KernelDecision\n```\n\n## Executor boundary before PR 16\n\nPR 15 does not create `pyruntimekit.executors`.\n\n`SimpleRunner` uses a private structural protocol that requires only:\n\n```python\nexecute(workload, context) -> ExecutionResult\n```\n\nPR 16 will introduce the actual Executor contract and InlineExecutor, then replace this temporary internal typing boundary without changing Runner semantics.\n\n## Run ownership\n\nThe Runner never assigns `Run.state`, version or attempt directly.\n\nIt asks RuntimeKernel to apply:\n\n- `StartRun` before execution;\n- `CompleteRun` for a successful normalized result;\n- `FailRun` for a normalized Failure.\n\nInvalid starting states are rejected by the Kernel's canonical transition matrix.\n\n## Attempt semantics\n\nThe Runner derives the next exact AttemptNumber:\n\n```text\nNone -> 1\nN    -> N+1\n```\n\nThe Kernel remains responsible for validating that progression.\n\n## ExecutionContext\n\nThe context is built only after `StartRun` succeeds, from the resulting RUNNING Run and selected AttemptNumber.\n\nCorrelation, tracing and context metadata are supplied explicitly by the caller. The Runner does not silently merge Run or Workload metadata.\n\n## Time\n\n`SimpleRunner` receives a callable clock. It does not call wall-clock time directly.\n\nThe clock supplies the StartRun and terminal transition timestamps. A future RuntimeContext/Clock abstraction may satisfy this dependency.\n\n## Result handling\n\nA successful ExecutionResult is converted into a logical RunResult while preserving:\n\n- value;\n- artifacts;\n- result metadata.\n\nA failed ExecutionResult must already contain a normalized Failure. Raw backend exception normalization is an Executor responsibility and remains deferred to PR 16.\n\n`RunnerOutcome` preserves:\n\n- the StartRun KernelDecision;\n- the ExecutionContext;\n- the technical ExecutionResult;\n- the terminal KernelDecision.\n\nThis retains both lifecycle decisions and their domain events until persistence/event sinks exist.\n\n## Non-goals\n\n`SimpleRunner` does not implement:\n\n- Executor backend mechanics;\n- raw backend exception normalization;\n- retry policy;\n- persistence;\n- cancellation;\n- timeout policy;\n- recovery;\n- worker ownership;\n- Runtime.submit().\n\n## Consequences\n\n- Runner orchestration can be qualified before InlineExecutor exists;\n- lifecycle authority stays centralized in RuntimeKernel;\n- PR 16 can add Executor contracts without moving lifecycle logic;\n- PR 17 can compose Runtime.submit() from Kernel + Runner + InlineExecutor.\n

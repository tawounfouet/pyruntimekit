# PyRuntimeKit 0.1.0a3 — Executor Conformance

## Status

**Conformance candidate.**

This record becomes **Qualified** after the standardized Executor matrix and the complete repository quality gate pass on the exact PR head.

## Scope

The conformance matrix covers the built-in local Executors available in the `0.1.0a3` milestone:

- `InlineExecutor`;
- `AsyncExecutor`;
- `ThreadExecutor`.

It verifies the common logical Executor contract without pretending that all backends have identical execution mechanics.

## Common contract

Every built-in Executor must demonstrate:

```text
successful execution
result normalization
existing ExecutionResult preservation
ordinary exception normalization
safe Failure payload
exact ExecutionContext delivery
Workload/ExecutionContext identity validation
stable descriptor identity
truthful capability declaration
no Run lifecycle ownership
```

## Backend-specific guarantees

### InlineExecutor

```text
direct execution
same process
same thread
shared memory
no concurrency capability
```

### AsyncExecutor

```text
explicit asyncio Task
ContextVar propagation and isolation
bounded active concurrency
CancelledError preserved as control flow
```

### ThreadExecutor

```text
same process
different thread
copy_context propagation
bounded in-flight pool submission
explicit pool cleanup
await cancellation does not imply thread termination
```

## Deferred timeout contract

`0.1.0a3` does not claim timeout or deadline execution semantics.

The conformance suite therefore does not emulate timeout behavior. It verifies that no timeout capability is silently advertised.

Timeout ownership remains deferred to the execution-control milestone.

## Architecture authority

Executor conformance does not change the authority rule:

```text
RuntimeKernel
=
Run lifecycle authority

Executor
=
execution mechanism
```

Built-in Executors remain independent from concrete Kernel/application lifecycle implementation.

The same parameterized scenarios run against all three built-in backends.

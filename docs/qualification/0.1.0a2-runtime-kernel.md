## Scope

This qualification covers the complete `0.1.0a2 — Runtime Kernel` local executable slice:

- RuntimeKernel commands, decisions and transition authority;
- immutable ExecutionContext;
- SimpleRunner orchestration;
- Executor contract and ResolvedWorkload;
- InlineExecutor;
- SubmissionService;
- public Runtime.submit();
- public RunHandle;
- normalized success and failure paths;
- package-wide architecture boundaries.

It builds on the already-qualified `0.1.0a1 — Domain Foundations`.

It does **not** qualify:

- async execution;
- ThreadExecutor / ProcessExecutor / SubprocessExecutor;
- persistence Stores;
- workers;
- cancellation;
- retry/recovery;
- checkpoints;
- effects;
- leases/fencing;
- distributed execution;
- observability transports.

Those belong to later milestones.

## Qualified vertical slice

The intended qualified path is:

```text
Python callable / ResolvedWorkload
            │
            ▼
       Runtime.submit()
            │
            ▼
     SubmissionService
            │
            ▼
       RuntimeKernel
 CREATED → ADMITTED → QUEUED
            │
            ▼
       SimpleRunner
            │
       RuntimeKernel
          RUNNING
            │
            ▼
      ExecutionContext
            │
            ▼
      InlineExecutor
            │
            ▼
     ExecutionResult
        /       \
   success     failure
      │           │
      ▼           ▼
 CompleteRun    FailRun
      │           │
      └─────┬─────┘
            ▼
       RuntimeKernel
      SUCCEEDED/FAILED
            │
            ▼
 ephemeral read registry
            │
            ▼
        RunHandle
```

## Lifecycle evidence

For both successful and failed submissions, the qualification suite requires exactly five Kernel decisions.

Success:

```text
version 0  CREATED    run.created
version 1  ADMITTED   run.admitted
version 2  QUEUED     run.queued
version 3  RUNNING    run.started
version 4  SUCCEEDED  run.succeeded
```

Failure:

```text
version 0  CREATED   run.created
version 1  ADMITTED  run.admitted
version 2  QUEUED    run.queued
version 3  RUNNING   run.started
version 4  FAILED    run.failed
```

Every emitted event must reference the same RunId, the resulting RunVersion and the resulting Run.updated_at timestamp.

## Authority boundaries

The qualified authority model is:

```text
Runtime
=
public composition facade

SubmissionService
=
use-case coordination

SimpleRunner
=
execution progression

RuntimeKernel
=
lifecycle authority

InlineExecutor
=
execution mechanism

RunHandle
=
client read reference
```

The qualification rejects dependency inversions that would move lifecycle semantics into Executor or application code.

## Persistence boundary

`0.1.0a2` has **no durable persistence guarantee**.

The only handle read model is the explicit process-local in-memory resolver introduced for the synchronous bootstrap.

The qualification suite rejects imports of common persistence technologies and direct file-write calls in production source.

Therefore:

```text
in-memory handle registry
≠ RunStore
≠ durable state
```

Persistence belongs to later milestones.

## Concurrency boundary

`0.1.0a2` has **no asynchronous or threaded execution guarantee**.

The package-wide architecture gate rejects hidden dependencies on:

```text
asyncio
threading
multiprocessing
subprocess
concurrent
queue
```

It also rejects hidden `sleep()` calls.

The qualified execution model is therefore:

```text
same caller process
same caller thread
synchronous completion
```

## RunHandle boundary

A RunHandle is qualified as:

```text
RunId
+
read resolver
```

and explicitly not as:

```text
live Run ownership
SubmissionOutcome ownership
Executor ownership
Kernel ownership
```

For this synchronous milestone, a returned handle already references a terminal execution, so `wait()` returns the existing terminal result without polling.

## Deferred semantics

The following are intentionally **not** claimed by this qualification:

- background execution;
- async Runtime;
- ThreadExecutor;
- cancellation requests;
- retry policy;
- durable RunStore;
- externally refreshable handles;
- event querying from RunHandle;
- distributed ownership;
- leases/fencing;
- recovery/checkpointing.

Absence from `0.1.0a2` is deliberate and must not be interpreted as partial support.

## Release boundary

A successful qualification means:

> PyRuntimeKit `0.1.0a2` has a coherent first executable local vertical slice with Kernel-owned lifecycle transitions, Runner-owned progression, InlineExecutor-owned execution mechanics, normalized success/failure behavior and a public Runtime/RunHandle API.

It does **not** mean that PyRuntimeKit is durable, asynchronous, threaded or distributed.

## Expected release statement

> PyRuntimeKit 0.1.0a2 introduces the first executable vertical slice: RuntimeKernel, ExecutionContext, SimpleRunner, InlineExecutor, Runtime.submit() and RunHandle, with normalized success/failure execution and explicit synchronous in-memory semantics.
